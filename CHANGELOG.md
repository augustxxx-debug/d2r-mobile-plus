# Changelog

[简体中文](CHANGELOG.zh-CN.md)

This changelog records changes introduced by **D2R Mobile Plus** relative to its upstream baseline. It does not restate the upstream release history. Entries describe implementation status; an unreleased entry is not a published binary release.

## [Unreleased]

- **Free Town Portal is now an option, off by default** (user, 2026-10-30): Options → Custom → "Free Town Portal (no tome/scroll)". Off: an empty ZR slot goes back to the game, the town portal skill is no longer added to the skill tree, and the touch portal button uses the Tome of Town Portal (or a scroll) on the character, consumed as in the original game; with none it shows "No Town Portal tome or scroll" and opens no portal. On: exactly the previous behaviour. Settings files from earlier versions count as off. If you turn it off during a run, a portal skill already bound to a button keeps working until you leave the game.

## [1.0.0-rc1.1] - 2026-10-30

Changes since 1.0.0-rc1 (2026-10-29, `v1.0.0-rc1` = `a2bb5c3`):

- Redone "Join the community / About" box: one card each for the QQ group and the website (or GitHub), each with its own Copy; free-software notice; version and credits in the footer; a single OK. The Chinese UI shows both the group number and the website. **While the box is open, touch and controller input go only to the box**: nothing reaches the pause menu / main menu underneath, the row that opened it moves aside so its highlight no longer shows, and OK is hit on the first tap.
- The website address now comes from the update manifest's `community.site` (strictly checked: `https://` plus a valid host name, no port, at most 60 characters, no `@ ? #`); without it the box behaves as in RC1.
- Controller: **the left stick moves like the D-pad on our own pages (Graphics, Custom, the box)** (the dominant axis stays locked until both axes are released, so diagonal pushes do not skip); the Game Difficulty row in Options → Gameplay joins the focus chain (Up from the first row enters it, left / right change the level, A adds one; no more Y); the inventory legend reads "Compare (hold)" (only in languages we translate; German, French, Italian, Polish, Japanese and Portuguese keep the original); the key cap next to Elysium on the character-creation page follows the controller type (Switch / Xbox / PS), and Up no longer sends focus to the off-screen Ladder row; the controller character list, info box and legend are back to console font sizes, so the Chinese level line is no longer clipped.
- Fixed: the large blank area in About / Credits on the iPhone Duo inner screen; the Spanish credits label overlapping the names; on a fresh install the touch main menu's "Join the community" button sat off to the right; the duplicate Credits block on the Custom page is removed.
- Known issues: in touch mode the experience line may occasionally not show (toggle "Show frame rate" once in Options → Graphics); **RT on an empty skill slot opens a free town portal** (upstream feature; the next release makes it an option, off by default); the character on the select screen flickers for a frame or two when switching controller / touch; on the iPhone Duo inner screen the NPC dialog jumps for one frame when it opens; ray-traced shadows (experimental, off by default) double up in underground levels; under free signing long 120 fps sessions get memory warnings (17 Pro, 34-minute run: not terminated, 647 MB headroom), to be fixed as a hard gate next release.

Everything below lists all changes in 1.0.0-rc1 and earlier relative to the upstream baseline (it also applies to 1.0.0-rc1.1).

- Known issue (experience line): in touch mode the experience line may occasionally not show (mostly on the first run after a fresh install); toggling "Show frame rate" once under Options → Graphics brings it back. To be fixed in the next release.
- Known issue (memory, free signing): per-process limit about 3375 MB; in long 120 fps sessions the footprint levels off near 2.7 GB with continuous system memory warnings but no termination; the known host-side leak is fixed and any residual growth is judged by the current candidate's own long run; gone with a paid account carrying `increased-memory-limit` (about 6 GB).

Up to 2 point lights (at most 4) at quarter resolution, the character's own light weakened to 0.8×; levels without a sun trace point lights only. Automatic levels 0–3 by GPU time, each level still ray traced (level 3: half-resolution sun, point lights off, static alpha-tested occluders original, dither-faded units as opaque silhouettes); a GPU hang pauses ray tracing for 120 s, a second hang turns it off for the run. **Experimental** ray-traced AO, off by default (`DM_RT_AO=1`), turns off from level 1. ### Fixed

- The Spanish credits label becomes the shorter "Gracias especiales": "Agradecimiento especial" ran into the names column in the About area on the iPhone Duo inner screen.
- About layout (reported by the user on the iPhone Duo inner screen): the duplicate "Credits" sub-block is removed from the About group on the Options "Custom" page -- the credits appear in one place, the box that "Community · View" opens; with no community value to show the whole group is hidden (no empty "About" title left). For the community box see "box redone" above.
- Three fixes picked from upstream d2r-mobile v2.1.0 (authors kept on the commits): **controller mode no longer crashes opening the mercenary inventory** — our key hints are removed from the game's bottom button legend when it hides, and no entry is added once it holds 8, since the original relayout reads a 9th slot out of bounds (upstream #134); **the widened stash no longer pushes the inventory further right each time the stash is closed with +** (upstream #152, with its regression test); **in touch mode the minimap comes back after the act-change cutscene** when "AutoMap Open On Load" is on (upstream #49).

- **"RT on drops one level at startup" and the tier 1 / 0 "shrink the startup reserve before the window" never reached players (review 14 Q14-01 / 02)**: the iOS shell first computes the startup reserve when it builds the game view, which used to come before the memory limit and the settings directory were handed to the host, so the decisions latched on defaults: RT turned on in settings never dropped a level and low-memory devices never shrank, only the test environment-variable paths worked. `didFinishLaunching` now hands both over first (`custom_early_init`) and the view is built after; the RT drop no longer latches when asked before the settings are read, and a red line is logged if the reserve is ever computed before that. Regression: `t_boot_order` (the reviewer's harness, ask-then-load in the real order) and `test_boot_order.py` (pins the shell's call order).
- **Occasional in-run hang ("stuck in MonsterHealth:ClearInfo", about 3 in 50 Mac runs, also seen on the Duo)**: guest-thread waits in the host (locks, condition variables, addresses, synchronization objects) relied on a single condition-variable signal. In the dumps the lock had been handed to the waiter and the waiter was marked woken, yet it still sat in the OS condition-variable wait: the OS layer lost that signal and the whole run froze. Waits now wake every 100 ms to re-check, so a lost signal costs at most one slice and logs a 「线程同步：丢唤醒自愈」 line (included in the diagnostics summary); the thread dump shows "已被唤醒 N ms" for such threads. Regression: `t_lock_stress` (8 threads contend for a guest lock the SDK way, then 3 signals are dropped; progress must resume within 1.5 s) with the negative control `t_lock_stress_old` (without slices it must detect the hang); TSan reports 0.
- Memory: dev packages no longer carry the Metal capture layer (Info.plist `MetalCaptureEnabled`) by default. With it on, resident memory grows every frame and never comes back (on the device about 190 MB per 300 frames even with ray tracing off; the long test was ended by the system for memory within seconds). Only capture packages from `DM_METAL_CAPTURE=1 run.sh build` carry it now, for `DM_GPU_CAPTURE` only; the boot log says "Metal 抓帧层：开 / 关".
- **Experimental** ray-traced shadow memory: when ray tracing is set up it gets a budget of 1/8 of the distance to the system memory limit (48–192 MB). If the default level fits, nothing changes; otherwise AO is not built, the mesh cache shrinks, and the floor becomes level 3, in that order. On a system memory warning the next frame releases the mesh cache, AO and (when point lights are unused) the point masks and steps down one level; two within 10 s go straight to the lowest level with the mesh cache cap halved; one level is loosened 60 s after the last warning, then one every 30 s. A working set larger than the mesh cache cap no longer evicts and rebuilds every frame (no new builds while the cache is full; those draws keep the original). Point masks unused at level 3 are released too. The log prefix "光追内存：" is in the share-log summary.
- **Experimental** ray-traced shadows apply only in a run: on the main menu / character select (no controlled player) they are switched off and released and the original shading runs; they are rebuilt on entering a run. The front end used to be ray traced too, and in the character-select close-up the character self-shadowed so deeply that the face went dark (`DM_RT_FRONTEND=1` keeps front-end ray tracing for comparison).
- **Experimental** ray-traced shadow look (RC1; ray tracing stays off by default):
  ① point lights replace only the lights the original game shadows (the light record's texel +2 .w is 0), so characters and summons no longer get a second shadow;
  ② soft shadows on by default at strength 2 (contact-hardening, `DM_RT_SOFT=0` restores hard shadows); character shadow edges are close to the original;
  ③ the ray origin uses a normal rebuilt from depth: lit faces move along the normal, removing the self-occlusion blotches on the shaded side of characters and summons; back faces (N·L < 0) are not traced and count as shadowed - the original darkens them through its shadow map, and writing them lit made the camera-facing dark sides of monsters, NPCs and walls brighter than the original (RC1 back-face fix); the normal is smoothed over a 2-pixel neighbourhood and soft shadows get a minimum blur radius of 2 pixels, so the back / lit boundary does not break into specks. The game camera is orthographic with reversed depth, and the near plane is decided per frame from the camera matrix; ray-traced AO, whose normal used to point down in the game, is corrected too;
  ④ when ray tracing is on at startup the render resolution drops one level (Native → Balanced, Balanced → Eco, Auto → closed-loop step 1), decided only at startup and capping the output for the run; a changed ray-tracing setting takes effect at the next launch (`DM_RT_RES_DROP=0` turns it off). Same scene on a Mac: every million pixels less in the startup reserve is about 50 MB less resident memory;
  ⑤ the share-diagnostics summary gains the 「光追质量：」 and 「光追降分辨率：」 lines;
  ⑥ monsters of the same type and ground decorations / trees of the same model (same mesh and orientation, different position) no longer knock out each other's shadows: instance dedupe compared only the rotation rows of the model matrix, not the translation, so the later one counted as "the same instance drawn by both cascades", stayed out of ray tracing and had its original shadow skipped too, and shadows came and went with the draw order (Mac diagnostic host: about 3.75 million false matches over 6600 frames of a Blood Moor fight, about 570 per frame on average; about 36 per frame at the camp).
  Known issues: at 120 FPS ray tracing drops to level 3 by frame time and soft shadows do not apply (measured on a 17 Pro); at 60 FPS large fights / loading hitches drop levels too; the shadow tip is about 14% longer than the original; from downgrade level 2 shadows are half-resolution and hard; toggling ray tracing mid-run changes the resolution only at the next launch; the back sides of thin geometry (fence logs, branches) are darker than the original (the original 1024 shadow map cannot cast that self-occlusion; Mac camp, same frame, back-face fix only: pixels more than 25% darker than the original 2.3% → 4.7%, more than 25% brighter 1.7% → 1.3%; with the dedupe fix as well 4.8% / 1.0%); surfaces the original keeps out of its shadow pass (cave walls, stalagmites, torch stands) are darker on their back sides too - back faces always count as shadowed, which is grounded only for closed casters in the original shadow pass (characters, monsters); at the camp the same-frame deviation from the original in both directions together goes 3.96% → 5.78% (Blood Moor 1.81% → 1.61%); when on-screen skinned / alpha-tested units exceed the export quota of 1024 per frame, or their instance slots reach the mesh cache cap, the alpha-tested ones (characters and monsters in the game fade with dithering, so they all are) use the original shadow map, so one unit can switch between a ray-traced and an original shadow; skinned meshes without alpha testing already use the original shadow when the cache cap is reached or allocation fails, but in the other over-limit cases (export quota full, per-frame slot busy, 128 slots full) they still enter ray tracing in their bind pose (wrong shadow shape; counted 0 in 107 Mac runs and 18 device logs), to be moved to the original shadow map in RC2; a refused slot does not itself trigger mesh eviction, so after a scene change old meshes are usually released after about 600–720 unused frames (earlier if a newly built mesh pushes the cache over its budget), and new units may use original shadows meanwhile; the reduced-resolution sun (1/2 at both levels 2 and 3) samples the block-centre pixel, half a pixel off the position the upsampling assumes, so for some sun directions back-face 0 still leaks onto adjacent lit pixels (auditor case, 1/2 resolution, four directions: 22 / 68 / 74 / 5 pixels); RC2 makes the upsampling interpolate at the actual sample positions (measured 13 / 12 / 4 / 10), and dark streaks remain on fur such as the bear's, more visible at downgrade levels 2 / 3 (the usual state at 120 FPS: hard shadows, no blur) - the normal rebuilt from depth is noisy on fur; left to RC2.
- **Experimental** ray-traced shadows, seventh-review fixes:
  ① frames that do not use the sun mask (hysteresis hold, failure, point lights only) used to bind a 1×1 white texture to the `_rt` variants, which read it by pixel coordinates and got 0 out of bounds, darkening the whole frame; they now bind a fully lit mask of the main target size, and when the bound mask does not cover the render target (not built yet, dynamic resolution just changed) the variant is not selected and the original shading runs (the regression test reads it on the GPU over the whole target the way the variants do);
  ② non-indexed quads are built in the ray tracing with the original rasterizer's topology (0,1,2,0,2,3 per 4 vertices) instead of a single triangle that left half of each occluder without a shadow; indexed quads, which the original does not draw, are not built either;
  ③ `rts_variant.py` fails as a whole with a non-zero exit when a required variant does not compile, replacing no product (generated in a staging dir first), so packaging stops; the variant tests are now unittest, registered in the iOS tests, and collecting 0 tests fails;
  ④ the ray-tracing GPU time statistics are read and reset in one go under the completion callback's lock (TSan regression).
- **Experimental** ray-traced shadows, eighth-review fixes:
  ① when the fully lit mask cannot be built (texture allocation failing under memory pressure) the allocation used to be retried, and a red line logged, on every main-pass draw; a failure now waits 60 frames before the next try and shades as original meanwhile, the red line is logged once per failing round, the counts (with "mask does not cover the render target" and indexed quads) go into the 600-frame 「光追阴影：没进原因」 line, and a successful build logs how many tries had failed; switching off resets the log quotas and the retry wait (failure-injection regression);
  ② `rts_variant.py` treats an existing product as fresh only when its `.metallib` and `.metal` are present with the right version, regenerating one whose library is missing; after generating it checks every product the run should have (fresh ones and the judge library included); the json is moved last; staging dirs left by a killed run are removed first; the packaging log counts metallibs.

See README.
- 120 FPS (experimental) on the iPhone 17 Pro measures about 60 FPS on average, typically 56–75 FPS, not 120. The cause is a combined bottleneck: the translation thread (CPU) and the GPU each take about 13–15 ms per frame. The 3D ratio reaches its 0.60 floor within about 1.5 minutes, so the MetalFX profiles differ by only about 1.5 ms. Eco render resolution cuts GPU time by about 30% (to roughly 10.4 ms), and the translation thread does not scale with resolution. Thermal state 2, no memory warnings. RC1 adds no automatic fallback to 60 FPS; the 120 FPS stop stays an experimental opt-in. "Fall back to 60 FPS pacing at thermal state ≥ 2" is on the RC2 backlog.
