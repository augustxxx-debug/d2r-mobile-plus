# Changelog

[简体中文](CHANGELOG.zh-CN.md)

This changelog records changes introduced by **D2R Mobile Plus** relative to its upstream baseline. It does not restate the upstream release history. Entries describe implementation status; an unreleased entry is not a published binary release.

## [Unreleased]

RC2 merges the iOS and Android lines: one tree, and both packages come from the same commit.

- **Android, from the iOS line**: the "Join the community" box (pause menu, main menu, Options → Custom → About); the pause menu has the same rows in touch and controller mode; Game Difficulty moves to Options → Gameplay; the touch portal badge counts only tomes and scrolls a press can use; auto-potion no longer overwrites a portal press in the same tick.
- **iOS, from the Android line**: the shared loading page for first-time preparation; the PLUS app icon; after a failed audio resume the sound card is reopened every 1.5 seconds; the D-pad hints under the belt in controller mode sit higher so they are fully visible; the frame-rate display uses the sampling shared by both platforms (1-second window, at most 2 updates a second); diagnostics redact CJK character names; the UI font replaces only code points the game font already has.
- **Android**: when the game's version manifest is too small the failure page now says the files are incomplete instead of naming the wrong version; the permission prompt also takes confirm and Enter keys.
- **Community links**: the loading page and the in-game box now check `community.site` by the same rule. A manifest whose only channel is invalid no longer clears the community links you already have, and the entry stays visible.
- **Android folder name**: game files now go in `Download/S2X/D2R Mobile Plus`. If that folder holds nothing and `Download/S2X/D2R Mobile` does, the old folder keeps working, so you do not need to move anything. Prompts and guides use the new name.
- **Android**: the community / About box shows the version; the diagnostics file name keeps the version and commit apart.
- **Crowded scenes**: the game's video memory pool 0 grows from 400 MB to 512 MB, which raises how many animated monsters can be on screen before the game crashes: about 70 before, and 72 now run for the full 5-minute test with room left (measured on the Mac; phones not yet checked). A scene that keeps adding monsters without limit can still run it out. This sets aside 112 MB more of the game heap; pages are used only when needed.
- **Android upgrade**: the first start after upgrading to this version prepares the game content again on the phone. If you made an import pack on a computer, make it again with this version.
- **Free Town Portal is on by default** (user, 2026-10-30; both platforms): new installs start with it on, and settings from RC1.2 and Android 1.0.1 / 1.0.2 are moved to on once when you upgrade. Those versions saved every option, so an old "off" cannot be told from the old default; if you had turned it off on purpose, turn it off again in Options → Custom and it stays off. Going back to one of those versions, saving settings there and upgrading again moves it to on once more, because they drop the marker.

## [1.0.0-rc1.2] - 2026-10-30

- **Free Town Portal is now an option, off by default** (user, 2026-10-30): Options → Custom → "Free Town Portal (no tome/scroll)". Off is the original game: no free portal skill in the skill tree, and the touch portal button uses the Tome of Town Portal (or a scroll) on the character, consumed as in the original game; with none it shows "No Town Portal tome or scroll" and opens no portal. On: the town portal skill appears under General Skills and works on whatever button you bind it to (e.g. LT + A), and the touch portal button casts it; neither needs a tome or scroll. An empty RT (ZR) is no longer used as a free town portal under either setting; it is an ordinary skill slot. Settings files from earlier versions count as off; turning it off during a run removes the skill at once and buttons bound to it become empty.
- **Controller: the Gameplay options page opens on the Game Difficulty row** (RC1.1 on-device B057, follow-ups B064): from the pause menu, after switching tabs with LB / RB, and after switching touch → controller on the page the focus lands on (or returns to) the difficulty row and Left / Right / A / Down stay with it; outside a run (main-menu Options) the uneditable row is skipped. Down hands the focus back to the row it came from even after the page was rebuilt.
- **Touch: the "Join the community" box responds at all three entries** (RC1.1 on-device B058): main menu, pause menu and Options → Custom → About. View / Copy / OK are hit even where the original hit-test gives the box no size, and a small finger drift while the box is open no longer turns into front-end scrolling.
- **Touch portal button: the badge counts only what pressing it can use** (B062): tomes with charges and scrolls in the first inventory page and the belt; stash and Horadric Cube contents are no longer counted, so the badge never shows a portal the button cannot open.
- **Auto-potion no longer swallows a portal press in the same tick** (B063): when health and mana potions fire automatically on the tick you press the portal button, the portal request is kept and the potion waits for the next tick.

## [Android 1.0.1] - 2026-10-30

Upgrade over 1.0.0 (same package name and signing certificate; saves and the game files on the phone stay). After the upgrade the first launch rebuilds its touch resources once.

- **First-launch failures explain themselves**: the app checks the game files it needs (`ExeFS/main`, `sdk`, the 18 resource archives, `.build.config` — `build.config` without the dot works too — and `build_manifest.psv`) against Switch 3.3.94012 before building and names what is wrong ("missing data/.build.config (a hidden file, copy it too)", "data/05-00000001.data has the wrong size: should be X bytes, is Y (probably not fully copied)"); after any other failure it checks the file contents too. The failure screen title says what kind of problem it is (incomplete files, wrong version, not enough space, internal error) with the next step, and a "Share Diagnostics" button (touch, or A on a controller) shares a scrubbed zip of the full logs. gen_log.txt starts with the verdict, then the device, free space and the file list.

Off is the original game: the touch portal button uses your Tome of Town Portal or a scroll, shows how many are left and greys out at zero. RT is never turned into a free portal. If you had bound the free portal skill to a button in 1.0.0, that binding is cleared on the upgrade; turn the option on and bind it again.

- **Known issues**: stack counts on the belt sit low on their slots; switching between touch and controller on the character select page makes the character flicker for one frame; switching from touch to controller while a shop is open leaves the shop cursor stuck (press B to close the shop and trade again). Only tested on an Adreno handheld (AYN Thor); not re-tested on a Dimensity / Mali phone.

First Android release (`android-v1.0.0` = `5b226fd`, shown as `1.0.0+170 · 5b226fd`). Download and checksums: [Releases](https://github.com/augustxxx-debug/d2r-mobile-plus/releases/tag/android-v1.0.0).

- **Touch and controller**: touch stick and skill buttons; a connected controller switches to controller mode, and menus, options and the copy buttons all work with it.

- **Stability**: broken shader pipelines are skipped automatically; texture compatibility fixes for some Mali phones; experimental features switch off after repeated abnormal exits; scrubbed diagnostic sharing.
- **Community**: the loading page shows the official free channels (website · QQ group) with one-tap copy.
- **Verify**: official builds are always signed with certificate SHA-256 `b4af06c165dd8699ab9f2b0dec8f6c2de05cd4d01f510fe63778eac6898a52da`.

### Development log

Everything below is the full list of changes on this branch relative to the upstream baseline (including parts shared with iOS), for developers.

Baseline: upstream [`195ae11`](https://github.com/jhaizhou-ops/d2r-mobile/commit/195ae11dc70f1ba7735c6063e1ed81102e1dbf52). Validation updated on **2026-10-26**.

### Android

- App icon reads "MOBILE PLUS" (from `AppIcon1024.png`, shared with iOS and Mac); the app is named **D2R Mobile Plus** with the package name `com.augustusplay.d2rmobileplus`.
- Arm Mali support (verified on a MediaTek Dimensity 9600 Pro phone, Mali-G2 Ultra, Android 17): load-time shader rewrites where the GPU needs them (a range guard for 32-lane warp shuffles on 16-lane subgroups, unused ClipDistance / CullDistance removed, NonWritable on read-only vertex buffers), the host page size read at run time (groundwork for 16 KB-page kernels; not yet verified on such a device), and on GPUs without BC textures the BC3 textures converted to ASTC 4x4 on load (decoded image memory 837 → 407 MB on that phone; textures with varying transparency lose a little alpha precision). Qualcomm phones keep sampling BC directly.
- Android performance hints (ADPF) for the busiest game threads and the system thermal status in the performance log; measured neutral on both test phones.
- From upstream v2.1.0: the 30 FPS power-saving setting is honoured on Android (it ran at 60 before); BC4 / BC5 decode to 8-bit channels where 16-bit R / RG cannot be filtered (a crash on some Mali phones); a compute or graphics pipeline that crashes or fails the driver's shader compiler is skipped from the next boot instead of crashing every boot; on Adreno 750–799 shader helper functions are inlined at load (the SPIRV-Tools library is compiled into the app; its licence is in the notices). The Adreno 740 keeps the quad-derivative and warp32 rewrites (the hang upstream saw there is fixed on this branch).
- Share diagnostics and the generator log redact shared storage under any user id (/storage/emulated/<n>), not only user 0.
- The first-launch loading page (import / on-phone generation) shows the official free channels at the bottom (project site · QQ group, "This app is free. If you paid for it, it was resold") with a button that copies the group number (tap, or A on a controller; "Copied" for 2 s); the permission screen now looks like the loading page. The values come from the remote update manifest (`latest.json`), fetched in a fixed order (our own server's subdomain, then its main domain, then GitHub raw; the next one only on a timeout, a non-200 answer or an invalid manifest), strictly validated, with the last valid one cached; nothing is shown when no manifest can be fetched, and there is no built-in default. This adds the INTERNET permission: the fetch runs only on launches where the game content is not prepared yet (the first launch, or a relaunch after an unfinished generation), at most one round per launch starting at the permission screen; on a very poor network it can take up to about 2 minutes and may still be finishing after the game starts. Once the content is prepared, starts make no network access. After an app update whose touch controls changed, the app prepares the content again by itself (about 6 minutes on the loading page, fetching the manifest once more) instead of stopping with an error. The addresses are set at packaging time (none = no network access).

- The Android package now makes the import pack on the phone (no computer needed): put your own `ExeFS` and `data` on the device and the app builds it on first launch. The package bundles the open-licence LXGW WenKai font (SIL OFL 1.1) for the Kai-style UI text; the former private Kai font is no longer used for public packages.
- Optional UI font: only the Chinese / Japanese glyphs the game font already has are replaced (no extra codepoints), and a composed font over 15 MiB is refused; a larger one crashed the Android main menu as soon as it drew text.
- Android package notices: the third-party components bundled for on-phone generation (CPython with OpenSSL / SQLite and the libraries it incorporates, NumPy, OpenBLAS, python-lz4, fontTools, Capstone, Pillow with FreeType / HarfBuzz / zlib-ng, zlib, SPIRV-Tools, the .NET NativeAOT shader translator with Ryujinx code) now ship with their licences as `assets/dmgen/THIRD_PARTY_NOTICES.txt`; the packaging script refuses a package without them or with versions that do not match the runtime. The generation failure log `gen_log.txt` is scrubbed of local paths and the package name before it is written to Download. A generated pack whose final swap was interrupted is generated again on the next launch instead of being taken for files pushed during development.
- Known issue: memory grows during the first hour of Android play (65-minute five-act run on an Adreno 740 handheld at the 60 FPS setting with three trips to the background: about 0.55 MB/s on the first pass through the 12 levels, 0.03 MB/s on the fourth, never closed by the system, no low-memory warning); longer sessions and phones with 8 GB of RAM or less are not tested. Restart the app if it gets slow after long play.
- The Android licence notices also cover the third-party code compiled into the app itself: the Kotlin standard library (added by the Android Gradle plugin), libdeflate, bcdec, the nvn.h declarations and the deko3d layout algorithm; libgfortran now ships with the full GPL-3.0 and GCC Runtime Library Exception texts.
- First Qualcomm Adreno candidate of the Android build (branch `claude/android-p0-e0b171`, not merged into the iOS line): crash fence lifecycle wiring, pause-menu Share diagnostics with redaction, version label from the shared `version.sh`, native output size with the Graphics Resolution level, the 120 FPS stop with automatic high-refresh display mode, Show frame rate on the overlay, physical controller support (Xbox layout, B / BACK consumed, controller / touch mode switching, the overlay keeps the experience line in controller mode), 3D brightening cap 2 by default, and two Adreno 740 driver workarounds in the Vulkan engine (the warp32 rewrite computes subgroup masks from the lane id after the driver hung on reading SubgroupLtMask word 1; a probe-gated lane-id-through-ballot rewrite). Mali devices are not covered by this candidate. Settings rows are gated per platform: the Custom-tab iCloud save-sync row exists only where iCloud does (the Android layout and host both omit it).
- Android first-audit fixes: Share diagnostics now redacts Chinese / Japanese / Korean character names even right next to Han text, and Latin names next to Han text, with longer names replaced first (the same rule on iOS / Mac in `dm_diagnostic_scrub.h`); the lane-id-through-ballot rewrite computes the lane id once in the entry function (every lane active) into a Private variable that helper functions read, so helpers called under divergent control flow get the real lane id, and it now uses ExclusiveScan (the old code used InclusiveScan, giving lane id + 1); the start-up lane-id probe unmaps its memory before freeing it and, when its fence wait does not complete, waits the queue idle before releasing anything (or keeps the objects if the queue cannot go idle). The release packaging script pins the release certificate (SHA-256 `b4af06c1…52da`) and never generates a new key.

State machine, progress composition, text and layout live in the shared host `dm/host/dm_loadpage.c`; the platform layers only draw and play music. The assets are self-made (CC0), except that on Android the backgrounds are now the app icon art (upstream icon plus our PLUS lettering, Cormorant Garamond, OFL) centred and faded to black, and the gold wordmark is no longer drawn there (the icon already reads MOBILE PLUS); the install package contains no original game assets. The share-log summary gains a 「加载页：」 line with the stage durations.
- **"Join the community" box redone** (user, 2026-10-30): one card per channel -- label, value and its own small "Copy", at most two rows. Chinese takes the first two present of "QQ group → website → GitHub", other languages "website → GitHub"; the website is shown without `https://` and the trailing `/`, GitHub as the repository name, and **Copy always copies the full value**, the button reading "Copied" / "Failed" for two seconds. Under the cards a free notice ("This app is free. If you paid for it, it was resold"), then a divider, the version, the maker and special thanks, and a single "OK"; the box height follows the number of rows. Controller: focus starts on the first "Copy", up / down moves between the Copy buttons and OK, A activates, B closes. While the box is up, taps and every controller input (D-pad, both sticks, other buttons) act only on the box and never reach the pause menu / main menu / options page underneath; stick up / down moves focus like the D-pad. The website comes from a new optional `site` in the version manifest's `community` (an https address, host plus optional path, no port, no `@` `?` `#`, over 60 characters counts as absent), never from code; without `site` the box shows the QQ group / GitHub as before. Older clients ignore the field.
- Font licence shipped with every package (13th review Q13-02): the build writes `UIFonts/FONT_LICENSE.txt` next to the generated font, holding a provenance and modification note (name, version, file, SHA-256; subset and merged with the game font under the game font's registration name) followed by the unmodified licence found beside `DM_UI_FONT`. A font under a `public` directory must have its licence file beside it or the build fails; a font under a `private` directory is accepted only with `DM_PRIVATE_FONT=1` and ships no licence. Three unit tests.

- The pause menu now uses **one row order for both input modes**: save and exit / quick restart / deposit / options / chronicle / share diagnostics / join the community (the upstream baseline had separate controller and touch menus; Options stays on the row where the controller cursor lands; under touch the deposit row is the same entry as the inventory button).
- **Game difficulty moved to Options → Gameplay**: a new "Difficulty" section at the top of the page with a "Game Difficulty: N" row (1–8, as if that many players were in the game); tap the slider's end arrows on touch, or on a controller move the focus onto it like any other row (Up from the first row below) and use Left / Right for one level down / up, or A for one level up (back to 1 after 8); it takes effect at once and is the same value as the touch bottom-bar difficulty cell; outside a game the row reads "Available once you are in a game". The pause menu no longer has a difficulty row. The share-log summary gains a 「游戏难度：」 line with the current level.
- In-game **community entry and About** (as of RC1; in RC1.1 the box contents and copying became channel cards, see "box redone" above): a "Join the community" row next to "Share Diagnostics" in the pause menu, a "Join the community" row on the front-end main menu (controller column under Options, Credits kept / centred right under Play on touch), and an "About" group at the end of the Custom options page ("Community · View"; the credits are in the box it opens); every "Join the community" opens the same in-game box, which shows a QQ group number with "Copy number" in the Chinese UI and the GitHub repository address with "Copy link" in every other language, plus an About section (display version, the byline "Made by Augustus", special thanks to the d2r-mobile author jhaizhou-ops) (iOS `UIPasteboard` / Mac `NSPasteboard`; "Copied" appears inside the box, no system popup). The number and link are not in the code: they come from the `community` field of the remote version file the update check already fetches (`{"qq_group": "…", "github": "https://github.com/…"}`), cached as `community.txt` in the settings directory; without the field the entry is hidden altogether, a failed fetch keeps the cache, and no cache means hidden. Works with touch, controller (D-pad selects the row, A copies, B dismisses) and Mac; the box text follows the original style sheet in three levels (title 48, body 36, secondary 28, original colour tokens and spacing); boot-log lines use the fixed prefix 「社区入口：」 and enter the share-log summary; sample manifest `docs/community_manifest.sample.json`, test switch `DM_TEST_COMMUNITY=<manifest file>` (read only in test runs).
- Experimental **120 FPS** stop on the Graphics frame-rate selector, shown only on screens with a maximum refresh rate of at least 120 Hz (stored as `eco_fps=2`; older builds read it as 30). On iOS, 120 FPS presents from the present thread instead of CAMetalDisplayLink, because the display-link path was composited at 60 Hz once the in-run UIKit overlay was on screen (every other frame dropped). Device-tested on an iPhone Duo inner screen with full effects (about 3 minutes, 0 system drops, 0.17% late; needs the Eco render resolution); power not measured; other devices untested. Diagnostic log lines 「帧率档：」 and the share-log summary record the effective frame rate and present path.
- **120 FPS (experimental) no longer offers MetalFX Quality** (user decision 2026-10-29, for memory headroom): with the 120 FPS stop selected the Graphics profile slider stops at Balanced and a grey subtext line (six languages) explains it; a saved Quality runs as Balanced at 120 and as Quality at 60 / 30, and the saved choice is kept. The 3D scale controller's Quality mode follows the same cap. New 「超分档位：」 log line and a combined `FPS target / profileSelected / profileEffective / qualityCapped120` line in the iOS diagnostic summary; Mac summary includes the log line. Regression tests in `t_render_profile` (including no change at 60 / 30 FPS), `test_touch_layout_options`, `test_sharelog_summary`.
- **Memory tiers by the per-process memory limit** (user decision 2026-10-29: devices differ in RAM). The limit (`phys_footprint + os_proc_available_memory`) is read in iOS `main.m` before the game heap is allocated. Tiers: ≥ 3200 MB unchanged; 2600–3199 MB hides 120 FPS (grey note on the Graphics frame-rate row, six languages) and defaults MetalFX to Eco and render resolution to Balanced; < 2600 MB also defaults render resolution to Eco and shows a one-time main-menu notice (the crash-fence in-game box, six languages). Defaults apply only on first run / tier change and only to values still at the old default; values the player changed are kept. On tiers 1 / 0, iOS `front_game_res` shrinks the startup render reserve to the launch resolution level before the game builds render targets (lowering mid-run returns no memory), so raising resolution needs a restart; a grey note on the resolution row says so, and the summary records launch and current values (`Memory tier=… atLaunch … now …`, 「内存档位预留：」 line). `DM_MEM_TIER=0/1/2` overrides. New 「内存档位：」 log line in the iOS and Mac diagnostic summaries. README support matrix is by memory tier, not a model list. Regression tests in `t_mem_tier` (thresholds, override, no side effect at ≥ 3200 MB, defaults, player changes kept, tier change, one-time notice, crash notice first, log line) and the layout / summary tests.
- **Experimental** Graphics tab **Ray-traced shadows (experimental)** switch, off by default and shown only on devices that pass `supportsRaytracing`, GPU family Apple9 or later and a model allowlist (iPhone 15 Pro / A17 Pro and later, iPad Pro M4 and later, Macs with M3 and later); Metal 4 path only. Current behaviour: shadow-pass draws enter cached per-mesh acceleration structures (content-keyed, at most 32 new meshes / 60,000 triangles per frame, 64 MB byte budget, released when switched off); characters and monsters use their real pose (skinned position export + refit); alpha-tested occluders are judged at each hit by the game's own fragment shader, rewritten at packaging. One occlusion ray per pixel goes toward the sun, taken from the largest square shadow map; sun shadow draws in the acceleration structure are not drawn into the shadow map, the rest are drawn as original, and 230 generated `_rt` fragment variants take the darker of the mask and the map (partial fallback); other maps (top-down soft shadow, hair) stay original; frames that cannot use the mask show the original shadows, with a hysteresis against flipping. Up to 2 point lights (at most 4) at quarter resolution, the character's own light weakened to 0.8×; levels without a sun trace point lights only. Automatic levels 0–3 by GPU time, each level still ray traced (level 3: half-resolution sun, point lights off, static alpha-tested occluders original, dither-faded units as opaque silhouettes); a GPU hang pauses ray tracing for 120 s, a second hang turns it off for the run. **Experimental** ray-traced AO, off by default (`DM_RT_AO=1`), turns off from level 1. Diagnostic lines 「光追阴影：」「光追降档：」「光追镂空：」「光追点光：」「光追 AO：」 are in the share-diagnostics summary. Fixes from the fifth and sixth review rounds and later device feedback are folded into this description (content-keyed meshes, fenced per-frame slots, byte budget, per-map handling, partial fallback, sun-map selection); the seventh-review fixes are listed under Fixed. Unit tests: `dm/gfx/tests/t_rts_gate.m`, `t_rts_span.m`, `t_rts_state.m`, `t_rts_flicker.m`, `t_rtshadow.m`. Status: runs on the Mac native host (about 2.8–4.0 ms GPU per frame at levels 0–2, 1.1–1.5 ms at level 3 on an M4 Pro); the current levels are **not yet validated on a device**; device frame rates are estimates; no power data.
