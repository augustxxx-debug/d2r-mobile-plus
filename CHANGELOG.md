# Changelog

[简体中文](CHANGELOG.zh-CN.md)

This changelog records changes introduced by **D2R Mobile Plus** relative to its upstream baseline. It does not restate the upstream release history. Entries describe implementation status; an unreleased entry is not a published binary release.

## [Unreleased]

Baseline: upstream [`195ae11`](https://github.com/jhaizhou-ops/d2r-mobile/commit/195ae11dc70f1ba7735c6063e1ed81102e1dbf52). Validation updated on **2026-10-26**.

### Added

- Font licence shipped with every package (13th review Q13-02): the build writes `UIFonts/FONT_LICENSE.txt` next to the generated font, holding a provenance and modification note (name, version, file, SHA-256; subset and merged with the game font under the game font's registration name) followed by the unmodified licence found beside `DM_UI_FONT`. A font under a `public` directory must have its licence file beside it or the build fails; a font under a `private` directory is accepted only with `DM_PRIVATE_FONT=1` and ships no licence. Three unit tests.

- The pause menu now uses **one row order for both input modes**: save and exit / quick restart / deposit / options / chronicle / share diagnostics / join the community (the upstream baseline had separate controller and touch menus; Options stays on the row where the controller cursor lands; under touch the deposit row is the same entry as the inventory button).
- **Game difficulty moved to Options → Gameplay**: a new "Difficulty" section at the top of the page with a "Game Difficulty: N" row (1–8, as if that many players were in the game); tap the slider's end arrows on touch, or press Y on a controller to go up one level (back to 1 after 8); it takes effect at once and is the same value as the touch bottom-bar difficulty cell; outside a game the row reads "Available once you are in a game". The pause menu no longer has a difficulty row. The share-log summary gains a 「游戏难度：」 line with the current level.
- In-game **community entry and About**: a "Join the community" row next to "Share Diagnostics" in the pause menu, a "Join the community" row on the front-end main menu (controller column under Options, Credits kept / centred right under Play on touch), and an "About" group at the end of the Custom options page ("Community · View" + credits); every "Join the community" opens the same in-game box, which shows a QQ group number with "Copy number" in the Chinese UI and the GitHub repository address with "Copy link" in every other language, plus an About section (display version, the byline "Made by Augustus", special thanks to the d2r-mobile author jhaizhou-ops) (iOS `UIPasteboard` / Mac `NSPasteboard`; "Copied" appears inside the box, no system popup). The number and link are not in the code: they come from the `community` field of the remote version file the update check already fetches (`{"qq_group": "…", "github": "https://github.com/…"}`), cached as `community.txt` in the settings directory; without the field the entry is hidden altogether, a failed fetch keeps the cache, and no cache means hidden. Works with touch, controller (D-pad selects the row, A copies, B dismisses) and Mac; the box text follows the original style sheet in three levels (title 48, body 36, secondary 28, original colour tokens and spacing); boot-log lines use the fixed prefix 「社区入口：」 and enter the share-log summary; sample manifest `docs/community_manifest.sample.json`, test switch `DM_TEST_COMMUNITY=<manifest file>` (read only in test runs).
- Experimental **120 FPS** stop on the Graphics frame-rate selector, shown only on screens with a maximum refresh rate of at least 120 Hz (stored as `eco_fps=2`; older builds read it as 30). On iOS, 120 FPS presents from the present thread instead of CAMetalDisplayLink, because the display-link path was composited at 60 Hz once the in-run UIKit overlay was on screen (every other frame dropped). Device-tested on an iPhone Duo inner screen with full effects (about 3 minutes, 0 system drops, 0.17% late; needs the Eco render resolution); power not measured; other devices untested. Diagnostic log lines 「帧率档：」 and the share-log summary record the effective frame rate and present path.
- **Experimental** Graphics tab **Ray-traced shadows (experimental)** switch, off by default and shown only on devices that pass `supportsRaytracing`, GPU family Apple9 or later and a model allowlist (iPhone 15 Pro / A17 Pro and later, iPad Pro M4 and later, Macs with M3 and later); Metal 4 path only. Current behaviour: shadow-pass draws enter cached per-mesh acceleration structures (content-keyed, at most 32 new meshes / 60,000 triangles per frame, 64 MB byte budget, released when switched off); characters and monsters use their real pose (skinned position export + refit); alpha-tested occluders are judged at each hit by the game's own fragment shader, rewritten at packaging. One occlusion ray per pixel goes toward the sun, taken from the largest square shadow map; sun shadow draws in the acceleration structure are not drawn into the shadow map, the rest are drawn as original, and 230 generated `_rt` fragment variants take the darker of the mask and the map (partial fallback); other maps (top-down soft shadow, hair) stay original; frames that cannot use the mask show the original shadows, with a hysteresis against flipping. Up to 2 point lights (at most 4) at quarter resolution, the character's own light weakened to 0.8×; levels without a sun trace point lights only. Automatic levels 0–3 by GPU time, each level still ray traced (level 3: half-resolution sun, point lights off, static alpha-tested occluders original, dither-faded units as opaque silhouettes); a GPU hang pauses ray tracing for 120 s, a second hang turns it off for the run. **Experimental** ray-traced AO, off by default (`DM_RT_AO=1`), turns off from level 1. Diagnostic lines 「光追阴影：」「光追降档：」「光追镂空：」「光追点光：」「光追 AO：」 are in the share-diagnostics summary. Fixes from the fifth and sixth review rounds and later device feedback are folded into this description (content-keyed meshes, fenced per-frame slots, byte budget, per-map handling, partial fallback, sun-map selection); the seventh-review fixes are listed under Fixed. Unit tests: `dm/gfx/tests/t_rts_gate.m`, `t_rts_span.m`, `t_rts_state.m`, `t_rts_flicker.m`, `t_rtshadow.m`. Status: runs on the Mac native host (about 2.8–4.0 ms GPU per frame at levels 0–2, 1.1–1.5 ms at level 3 on an M4 Pro); the current levels are **not yet validated on a device**; device frame rates are estimates; no power data.

- Controller mode keeps the experience line (`Lv · % · FPS`) on both platforms: the touch overlay is no longer hidden as a whole, it draws only that line per the shared `dm/host/dm_hud_mask.h` (the original controller bar has its own life / mana numbers). Android: the Custom page no longer rings when the controller selects a row that cannot fully scroll into view (`dm_custom_scroll.h`).
- Graphics tab **Show frame rate** switch, second row, on by default (moved from the Custom tab, where it was off by default, at the user's request on 2026-10-28): the actual presented frame rate, refreshed every 0.5 s, is appended to the bottom-bar experience line ("Lv 17 · 23% · 60 FPS") in the same game-font glyphs and color, without a backing plate; it is hidden whenever the bar is (e.g. with a panel open). `DM_FPS=120` with `DM_PRESENT_HZ=120` is a 120 Hz experiment switch for the pacer, ProMotion request and 3D scale controller; not a settings option.
- Auto render resolution closed loop: with the 3D ratio at its floor and frames still dropping, the output steps down (Balanced → Eco) and recovers after 60 s clean; pure controller `dm_res_auto_step` in `dm/host/dm_res_cap.h` with unit tests, driven from the existing frame-interval controller in `hle_oe.c`. Not device-verified yet.
- Graphics tab **Resolution** slider (Auto / Eco / Balanced / Native) capping the whole-frame output size by pixel budget (4.0 / 2.07 / 2.8 MP / none), aimed at very dense screens such as the iPhone Duo inner screen where the UI layer, final composite and present blit at 2852x2006 dominate GPU time regardless of the 3D ratio. Shrink-only, aspect-preserving, applies live, defaults keep regular iPhones unchanged. Pure budget math in `dm/host/dm_res_cap.h` with unit tests; localized in six text sets. Implemented and unit-tested; not yet device-verified or power-measured.
- Auto render resolution now picks its pixel budget by GPU generation parsed from the Metal device name (A16 and earlier 2.07 MP, A17 Pro / A18 2.8 MP, A18 Pro / A19 3.8 MP, A19 Pro / A20+ 4.0 MP, M series 4.5 MP); screens above 4.5 MP native (the iPhone Duo inner screen) take the Balanced 2.8 MP budget, after a 10-minute device run under full-screen spell effects showed Native pinned at ~15 ms GPU per frame and Eco at ~10 ms with identical fps and dropped frames. Unit-tested; the GPU-generation table is not device-verified on older chips.
- Launch-time detection of an iPhone running the package with the iPad identity (a re-signing tool's "iPad mode"), which makes iOS letterbox the game at the iPad aspect ratio: logged as a failure and shown once as an alert with the fix. Diagnosed from a user report on iPhone 16 Pro; the shipped package itself is universal.
- Measurement build switch: `DM_DIAG_SAMPLING=1 dm/ios/run.sh build`, or a `Documents/diag_sampling.txt` file on any build, turns on per-pass GPU timing, per-thread CPU and heat-attribution sampling into `Documents/diag/`. Diagnostic output only; never set for release builds.
- Added on-device Graphics settings and notification screenshots to both READMEs, with image metadata removed. Graphics screenshots now show the five-tab revision and use distinct filenames.

- Dedicated Graphics tab (second in Options, right after Audio; rows are render resolution, frame rate, then the MetalFX switch and profile, so render resolution is not next to upscaling) with an independent MetalFX enable switch (labelled experimental), a four-position profile slider, and a separate left/right 30 / 60 FPS selector. Help uses smaller, muted secondary text. New labels and application guidance are localized in Chinese, English, Spanish, Latin American Spanish, Russian and Korean.

- Experimental MetalFX spatial upscaling with Auto, Eco, Balanced, Quality and Original profiles. Apply switches profiles live without restarting; render-target recreation may briefly pause rendering. Only 3D color is scaled, retaining the original mask and subsequent UI. Unsupported devices or initialization failure use the original pass.

- Adaptive front-end scene coverage and bottom-edge layout, with a centered interface and safe-area-aware positioning.
- Notification frame generation using locally supplied game artwork. Corner ornaments remain unstretched; the center uses an opaque shaded background.
- Optional build-time main-font override through `DM_UI_FONT`, including original-font fallback for missing characters. Disabled by default; no font files are distributed.
- Stroke-darkening levels for the optional font: `DM_UI_FONT_WEIGHT=0..8` widens every stroke of the requested font by 5‰ em per level (FreeType-style outline emboldening in `font_override.py`), re-centred so advances, line metrics, fallback glyphs and private-use icons stay unchanged; levels 2–3 fill in the grey hairlines of a kai face without turning it bold, level 6 reaches the ink density of the original `BlizzardGlobal`. New `font_sample.py` renders Mac sample sheets, including a simulation of the Graphics Resolution cap (text rasterised at the smaller output size and upscaled whole-frame), which is why lowered render resolutions soften UI text; the vector font cannot pre-compensate the upscale, so the documented trade-off is a heavier level with Auto/Balanced. Implemented and unit-tested (three new tests); Mac samples and macOS App runs at levels 2 and 4; on an iPhone Duo level 4 was too dark and **level 3 was accepted by eye** (full panel coverage pending).
- Focused regression tests for front-end coordinate conversion, quest-control classification, notification frame construction and font composition.
- English and Simplified Chinese project, build, verification and change documentation.

### Fixed

- Memory: dev packages no longer carry the Metal capture layer (Info.plist `MetalCaptureEnabled`) by default. With it on, resident memory grows every frame and never comes back (on the device about 190 MB per 300 frames even with ray tracing off; the long test was ended by the system for memory within seconds). Only capture packages from `DM_METAL_CAPTURE=1 run.sh build` carry it now, for `DM_GPU_CAPTURE` only; the boot log says "Metal 抓帧层：开 / 关".
- **Experimental** ray-traced shadow memory: when ray tracing is set up it gets a budget of 1/8 of the distance to the system memory limit (48–192 MB). If the default level fits, nothing changes; otherwise AO is not built, the mesh cache shrinks, and the floor becomes level 3, in that order. On a system memory warning the next frame releases the mesh cache, AO and (when point lights are unused) the point masks and steps down one level; two within 10 s go straight to the lowest level with the mesh cache cap halved; one level is loosened 60 s after the last warning, then one every 30 s. A working set larger than the mesh cache cap no longer evicts and rebuilds every frame (no new builds while the cache is full; those draws keep the original). Point masks unused at level 3 are released too. The log prefix "光追内存：" is in the share-log summary.
- **Experimental** ray-traced shadows apply only in a run: on the main menu / character select (no controlled player) they are switched off and released and the original shading runs; they are rebuilt on entering a run. The front end used to be ray traced too, and in the character-select close-up the character self-shadowed so deeply that the face went dark (`DM_RT_FRONTEND=1` keeps front-end ray tracing for comparison).
- **Experimental** ray-traced shadows, known issues (fixed in RC2): characters may show a doubled shadow; shadows are hard-edged and do not yet look as good as the original soft shadows. Ray tracing stays off by default.
- **Experimental** ray-traced shadows, seventh-review fixes:
  ① frames that do not use the sun mask (hysteresis hold, failure, point lights only) used to bind a 1×1 white texture to the `_rt` variants, which read it by pixel coordinates and got 0 out of bounds, darkening the whole frame; they now bind a fully lit mask of the main target size, and when the bound mask does not cover the render target (not built yet, dynamic resolution just changed) the variant is not selected and the original shading runs (the regression test reads it on the GPU over the whole target the way the variants do);
  ② non-indexed quads are built in the ray tracing with the original rasterizer's topology (0,1,2,0,2,3 per 4 vertices) instead of a single triangle that left half of each occluder without a shadow; indexed quads, which the original does not draw, are not built either;
  ③ `rts_variant.py` fails as a whole with a non-zero exit when a required variant does not compile, replacing no product (generated in a staging dir first), so packaging stops; the variant tests are now unittest, registered in the iOS tests, and collecting 0 tests fails;
  ④ the ray-tracing GPU time statistics are read and reset in one go under the completion callback's lock (TSan regression).
- **Experimental** ray-traced shadows, eighth-review fixes:
  ① when the fully lit mask cannot be built (texture allocation failing under memory pressure) the allocation used to be retried, and a red line logged, on every main-pass draw; a failure now waits 60 frames before the next try and shades as original meanwhile, the red line is logged once per failing round, the counts (with "mask does not cover the render target" and indexed quads) go into the 600-frame 「光追阴影：没进原因」 line, and a successful build logs how many tries had failed; switching off resets the log quotas and the retry wait (failure-injection regression);
  ② `rts_variant.py` treats an existing product as fresh only when its `.metallib` and `.metal` are present with the right version, regenerating one whose library is missing; after generating it checks every product the run should have (fresh ones and the judge library included); the json is moved last; staging dirs left by a killed run are removed first; the packaging log counts metallibs.
- **Experimental** ray-traced shadows, ninth-review fix: when two packaging runs shared one variant output directory, the later `rts_variant.py` used to delete the staging dir the earlier one was still using and make it fail; the whole run now holds a lock file next to the output directory (a later run waits for the earlier one), staging dir names carry the owner's pid and start time and only those whose owner is gone are removed, and the packaging copy leaves staging dirs out (two-process barrier regression).
- `DM_FPS=120` without `DM_PRESENT_HZ=120` no longer stalls the game: the host pacer now follows the 120 FPS target, and while the display link drives presents its target can no longer drift ahead of real time (it used to drift tens of seconds, and one late link callback then put the acquire fallback to sleep until then).

- Route enhanced UI notifications through a bounded queue drained on the game main thread. Paused-menu deposit feedback no longer waits for the server to resume; controller gold/item tooltips no longer move the notice.
- Fit the notification frame to native font measurements, preserving fixed corner and medallion art with single-frame slices. Sprite and widget writes both require matching ownership, frame and atlas checks. Common modal backgrounds share the game-art treatment while retaining native controls and actions.
- Diagnostic exports now include applied Graphics/MetalFX state and bounded log tails, with export-only redaction of recognized identifiers and known character names. Original logs remain unchanged.

- Settings tab labels now use a local, non-wrapping text style, including the controller layout's inherited style. This keeps English Gameplay on one line without changing tab artwork, hit rectangles or destinations.

- MetalFX can now activate from a recognized native 1:1 pass, without waiting for frame drops to lower resolution first. Off/unsupported/failed paths retain the original scaler, and switching away from Auto resets its recovery sampling.

- Preserved frame-time resolution reductions when Auto changes its thermal/power cap; raising the cap no longer resets the frame-time controller. The game thread consumes one absolute target to avoid transient cap/level mismatches. Added production-entry regression coverage, rapid cap-change checks, and a disabled-controller fallback check.

- Fixed Graphics incorrectly replacing Game Settings and hiding the native offline Terror Zones control. Settings now has five distinct destinations in the same touch/controller order: Audio, Gameplay, Settings, Graphics, Custom. Native Audio, Gameplay and Settings layouts were compared against the pre-Graphics version: five are byte-identical, and controller Game Settings changes only table row height to prevent divider overlap. Added preservation, tab-artwork and new-layout path regression coverage.

- Font composition now falls back to original visible glyphs when the selected font maps a character to an empty placeholder. Language choices have additional space and smaller text to avoid wrapping with replacement fonts.

- Preserved upstream global defaults across Graphics and Custom, including pending changes on the other enhanced tab; language and voice remain unchanged.

- Widened localized system notifications in touch and controller layouts, with text insets that keep longer English sentences clear of the decorative ends.

- Optional font composition now removes incompatible custom-only vertical tables and preserves original private-use game symbols, preventing merge failures and icon replacement.
- Live upscale changes preserve an explicit dynamic-resolution floor override.

- Misalignment between character-list content and its frame, off-center class creation actions and raised front-end bottom controls.
- A stale selected-tab outline and native hover/focus state when switching game panels.
- Placement of both lower-right indicator families: the layered fire-logo loading animation and the red save/loading symbol. Placement is prepared while hidden, and redundant resolution transitions are avoided.
- Quest narration controls ignoring stationary touches held past the ordinary **0.35-second** tap limit. The exception is restricted to quest-log controls; dragging, cancellation and other touch targets retain their existing behavior.

### Validation

- Audit build `c7ea42a`: user-confirmed physical Xbox navigation across all five settings tabs, Graphics controls and Apply, plus landscape inner/outer-screen folding on Graphics. Final configuration: 60 FPS + Quality. Loading transitions and other panel/modal combinations remain outside this acceptance.

- Dedicated Graphics settings passed device touch tests and a user-confirmed physical Xbox controller test, including left/right 30 / 60 FPS selection. The final configuration was 60 FPS with Quality.
- The user confirmed landscape fold/unfold transitions on the Graphics page across inner and outer displays. Menu/loading transitions and all other pages still require broader coverage.
- Profile migration, persistence and Apply/Discard/global Defaults semantics passed **195 checks**. The iOS touch suite passed **49 cases / 4,487 checks**; host UI classification passed **381 checks** and front-end geometry passed **44 checks**.
- Metal 3 and Metal 4 upscalers each passed **64 color/mask samples** and invalid-extent rejection. Device traces also recorded live changes between original rendering and all four upscaling profiles without restarting.
- Font composition passed **6 tests**, including empty mapped-glyph fallback; asset-cache contracts passed **14 tests**. Chinese and English Graphics/Custom pages were inspected on device, including notification width and language-choice labels.
- Earlier device traces reproduced the quest-log issue on the baseline: a stationary **0.8-second** release emitted no click. Both quick and 0.8-second releases stopped narration after the fix. Prior loading-indicator review covered 44 captured frames; this does not establish every transition is stable.
- Native-write, widget-cache, input-mode and localization gates passed; **475 localization entries** are synchronized. The signed iOS device build succeeded. Three tests requiring private native-binding fixtures were skipped because those fixtures are not distributed.

### Experimental / pending validation

- Font composition has synthetic-font coverage; an actual **ARKai_T / AR ZhongkaiGBK Medium** font was inspected locally in Chinese and English settings; complete English/Chinese panel coverage remains pending. This changes the shared main font and generated text that uses it, not every decorative face or bitmap label.
- Graphics-page physical controller and fold transitions are confirmed; other controller flows, folding during loading and all panel/achievement combinations remain pending. The preview does not claim universal UI correctness.
- MetalFX spatial upscaling is implemented; frame interpolation is not. An initial matched-map scripted combat power probe is complete. Power Profiler returned only an approximately 0.95-second snapshot per profile, and thermal states were not fully matched; readings are exploratory raw observations only, with no profile ranking, savings percentage or wattage claim. See README.

### Distribution

- `main` retains the upstream baseline; `codex/plus` carries the enhancement preview.
- Only source and documentation are published. Game-derived resources, local diagnostics, saves, signing material and commercial font files are excluded.
