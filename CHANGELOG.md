# Changelog

[简体中文](CHANGELOG.zh-CN.md)

This changelog records changes introduced by **D2R Mobile Plus** relative to its upstream baseline. It does not restate the upstream release history. Entries describe implementation status; an unreleased entry is not a published binary release.

## [Unreleased]

Baseline: upstream [`195ae11`](https://github.com/jhaizhou-ops/d2r-mobile/commit/195ae11dc70f1ba7735c6063e1ed81102e1dbf52). Validation updated on **2026-10-26**.

### Android

- Arm Mali support (verified on a MediaTek Dimensity 9600 Pro phone, Mali-G2 Ultra, Android 17): load-time shader rewrites where the GPU needs them (a range guard for 32-lane warp shuffles on 16-lane subgroups, unused ClipDistance / CullDistance removed, NonWritable on read-only vertex buffers), the host page size read at run time (16 KB pages), and on GPUs without BC textures the BC3 textures converted to ASTC 4x4 on load (decoded image memory 837 → 407 MB on that phone; textures with varying transparency lose a little alpha precision). Qualcomm phones keep sampling BC directly.
- Android performance hints (ADPF) for the busiest game threads and the system thermal status in the performance log; measured neutral on both test phones.
- From upstream v2.1.0: the 30 FPS power-saving setting is honoured on Android (it ran at 60 before); BC4 / BC5 decode to 8-bit channels where 16-bit R / RG cannot be filtered (a crash on some Mali phones); a compute or graphics pipeline that crashes or fails the driver's shader compiler is skipped from the next boot instead of crashing every boot; on Adreno 750–799 shader helper functions are inlined at load (the SPIRV-Tools library is compiled into the app; its licence is in the notices). The Adreno 740 keeps the quad-derivative and warp32 rewrites (the hang upstream saw there is fixed on this branch).
- Share diagnostics and the generator log redact shared storage under any user id (/storage/emulated/<n>), not only user 0.

- The Android package now makes the import pack on the phone (no computer needed): put your own `ExeFS` and `data` on the device and the app builds it on first launch. The package bundles the open-licence LXGW WenKai font (SIL OFL 1.1) for the Kai-style UI text; the former private Kai font is no longer used for public packages.
- Optional UI font: only the Chinese / Japanese glyphs the game font already has are replaced (no extra codepoints), and a composed font over 15 MiB is refused; a larger one crashed the Android main menu as soon as it drew text.
- Android package notices: the third-party components bundled for on-phone generation (CPython with OpenSSL / SQLite and the libraries it incorporates, NumPy, OpenBLAS, python-lz4, fontTools, Capstone, Pillow with FreeType / HarfBuzz / zlib-ng, zlib, SPIRV-Tools, the .NET NativeAOT shader translator with Ryujinx code) now ship with their licences as `assets/dmgen/THIRD_PARTY_NOTICES.txt`; the packaging script refuses a package without them or with versions that do not match the runtime. The generation failure log `gen_log.txt` is scrubbed of local paths and the package name before it is written to Download. A generated pack whose final swap was interrupted is generated again on the next launch instead of being taken for files pushed during development.
- Known issue: memory grows during the first hour of Android play (65-minute five-act run on an Adreno 740 handheld at the 60 FPS setting with three trips to the background: about 0.55 MB/s on the first pass through the 12 levels, 0.03 MB/s on the fourth, never closed by the system, no low-memory warning); longer sessions and phones with 8 GB of RAM or less are not tested. Restart the app if it gets slow after long play.
- The Android licence notices also cover the third-party code compiled into the app itself: the Kotlin standard library (added by the Android Gradle plugin), libdeflate, bcdec, the nvn.h declarations and the deko3d layout algorithm; libgfortran now ships with the full GPL-3.0 and GCC Runtime Library Exception texts.
- First Qualcomm Adreno candidate of the Android build (branch `claude/android-p0-e0b171`, not merged into the iOS line): crash fence lifecycle wiring, pause-menu Share diagnostics with redaction, version label from the shared `version.sh`, native output size with the Graphics Resolution level, the 120 FPS stop with automatic high-refresh display mode, Show frame rate on the overlay, physical controller support (Xbox layout, B / BACK consumed, controller / touch mode switching, the overlay keeps the experience line in controller mode), 3D brightening cap 2 by default, and two Adreno 740 driver workarounds in the Vulkan engine (the warp32 rewrite computes subgroup masks from the lane id after the driver hung on reading SubgroupLtMask word 1; a probe-gated lane-id-through-ballot rewrite). Mali devices are not covered by this candidate. Settings rows are gated per platform: the Custom-tab iCloud save-sync row exists only where iCloud does (the Android layout and host both omit it).
- Android first-audit fixes: Share diagnostics now redacts Chinese / Japanese / Korean character names even right next to Han text, and Latin names next to Han text, with longer names replaced first (the same rule on iOS / Mac in `dm_diagnostic_scrub.h`); the lane-id-through-ballot rewrite computes the lane id once in the entry function (every lane active) into a Private variable that helper functions read, so helpers called under divergent control flow get the real lane id, and it now uses ExclusiveScan (the old code used InclusiveScan, giving lane id + 1); the start-up lane-id probe unmaps its memory before freeing it and, when its fence wait does not complete, waits the queue idle before releasing anything (or keeps the objects if the queue cannot go idle). The release packaging script pins the release certificate (SHA-256 `b4af06c1…52da`) and never generates a new key.

### Added

- **Loading page for importing / preparing game content** (one implementation for iOS and Android): replaces the plain-text first screens with a self-drawn dark-fantasy background (landscape / portrait, cover-cropped to the screen, never stretched), a centred wordmark, a progress bar with percentage, a detail line (file N of M, bytes done / total, speed, time left), one hint line and loop music; on Android the import and shader-cache stages advance continuously on the same page (weighted by measured durations), iOS has the single download / import stage. State machine, progress composition, text and layout live in the shared host `dm/host/dm_loadpage.c`; the platform layers only draw and play music. All assets are self-made (CC0); the install package contains no original game assets. The share-log summary gains a 「加载页：」 line with the stage durations.
- Experimental **120 FPS** stop on the Graphics frame-rate selector, shown only on screens with a maximum refresh rate of at least 120 Hz (stored as `eco_fps=2`; older builds read it as 30). On iOS, 120 FPS presents from the present thread instead of CAMetalDisplayLink, because the display-link path was composited at 60 Hz once the in-run UIKit overlay was on screen (every other frame dropped). Device-tested on an iPhone Duo inner screen with full effects (about 3 minutes, 0 system drops, 0.17% late; needs the Eco render resolution); power not measured; other devices untested. Diagnostic log lines 「帧率档：」 and the share-log summary record the effective frame rate and present path.
- **Experimental** Graphics tab **Ray-traced shadows (experimental)** switch (off by default; the row is shown only on devices that pass all three checks: `supportsRaytracing`, GPU family Apple9 or later, and a model allowlist — iPhone 15 Pro / A17 Pro and later, iPad Pro M4 and later, Macs with M3 and later). When on, the translation layer still draws the game's two 1024² cascaded shadow maps as a fallback, and every shadow-pass draw also becomes an instance of a cached per-mesh acceleration structure (positions decoded by a compute kernel, static meshes built once, up to 12 new meshes per frame), the sun direction comes from the shadow pass's light view-projection, and right before the main opaque pass a compute kernel reconstructs each pixel from the depth prepass and traces one occlusion ray toward the sun into an R8 mask at 3D size. 230 `<key>_rt` fragment shader variants (generated by `dm/gfx/tools/rts_variant.py` at packaging, wired in since phase 2) read the mask in place of the cascade `sample_compare` (taking the darker of the two); `DM_RT_SHADOW_DBG=1` additionally multiplies the mask onto the HDR in one fullscreen pass for debugging. The shadow maps cleared this frame are cleared back to fully lit before the main pass only when the trace succeeded and every shadow-pass draw of the frame is in the acceleration structure (a map the game keeps across frames and did not clear this frame is left as drawn, and the variants take the darker value), so a frame that cannot be ray traced keeps its original shadows; after a failure the following frames skip tracing with a backoff (fifth and sixth review fixes). Mesh keys digest the whole index and vertex range, the mesh cache has a byte budget (`DM_RT_SHADOW_CACHE_MB`, default 64) and is released when the switch is turned off, and the per-frame constant / instance slots are reused only after the GPU has finished with them. Point-light cube shadows are unchanged. Skinned units cast shadows through position-export variants (phase 2). Metal 4 path only; `DM_RT_SHADOW=0/1` pins the switch for testing, `DM_RT_SHADOW_DBG=1` shows the mask as a multiply overlay. Status: implemented; runs on the Mac native host, device validation in progress.
- **Experimental** ray-traced shadows phase 2 (same switch, still off by default): ① packaging now generates the `_rt` fragment variants and the `_pos` skinned vertex variants every time (`dm/gfx/tools/rts_variant.py`, fresh ones skipped), so a phone package no longer lacks the variants and falls back to the fullscreen mask overlay; ② characters and monsters cast shadows in their real pose — in the shadow pass a skinned draw is encoded with the `_pos` vertex variant and rasterization off to export the skinned positions, which are refit from the bind-pose acceleration structure into a per-instance slot (up to 64 slots per mesh, 256 instances per frame) instead of using the bind pose; ③ point-light shadows — every frame up to 4 point lights (`DM_RT_POINT_N`, `DM_RT_POINT=0` disables) are picked by "close to the screen-center view line, bright", one occlusion ray per pixel each at half resolution, and the `_rt` variants look the mask up by light record index at the point-light cube-shadow sample while every other light stays as is; ④ alpha-tested occluders (foliage and other draws whose fragment may discard) keep rasterizing into the original cascades and the `_rt` variants take min(ray-traced mask, original sample); triangle-strip occluders are expanded into lists for the acceleration structure; ⑤ optional soft shadows (`DM_RT_SOFT=<strength>`, default 0 = hard): the sun ray takes the nearest hit and records its distance, then two depth-aware blur passes with a radius growing with blocker distance (near hard, far soft); ⑥ levels without a sun (indoor / underground, no shadow pass in the frame) register occluders from the depth-prepass draws, trace point lights only, keep the sun mask fully lit and darken nothing; ⑦ the character's own light (the "light radius" point light), recognized by "offset from the screen-center view line constant for 60 frames while the camera moves", is weakened to 0.8× by default (`DM_RT_PLAYER_LIGHT`, 1 = untouched; only while ray tracing is on); ⑧ fifth-review fixes merged: explicit mesh states (pending / submitted / usable) and a per-frame readiness gate — every shadow draw that did not enter the acceleration structure (new, pending, unsupported, quota or instances full) draws the original shadow map and the `_rt` variants keep those shadows through min; a frame whose ray tracing was incomplete (no main pass / camera, a shadow pass without a sun, mask not computed or not composited) falls back to the original shadow map and retries after 2 … 512 frames; the mesh fingerprint reads validated bytes only and the whole vertex range is checked (`t_rts_span`, `t_rts_state` regression tests, failing 10 / 14 checks on the previous code); ⑨ sixth-review fixes and review phase 0 merged: shadow maps are always drawn as original and cleared back to fully lit before the main pass only when ray tracing succeeded and every shadow draw of the frame is in the acceleration structure (a failing frame keeps its shadows); the mesh key covers every validated index byte and vertex attribute 0; per-frame buffers live in a fenced slot ring (≤ 8); the mesh cache has a 64 MB byte budget (`DM_RT_SHADOW_CACHE_MB`) and is released when switched off; `_rt` variants only for depth-tested, unblended main-pass draws; no fullscreen darkening when variants are missing; point lights are gathered on the GPU through the cluster tables, 2 by default with hysteresis, and the player light is weakened in a derived copy without writing game memory (`t_rts_gate` 37, `t_rts_span` 31, `t_rts_state` 39 checks, `t_rtshadow` pass). The Mac unit test `dm/gfx/tests/t_rtshadow.m` runs decode / acceleration structures / refit / sun and point rays / soft shadows / player-light recognition on a synthetic scene. The ray-tracing compute pass goes through the per-pass GPU timer; the 600-frame 「光追阴影：第 N 帧」 statistics line reports instances / variants / point lights / GPU ms, and the share-diagnostics summary carries that line and the 「光追点光」 line. Device and Mac validation pending; soft shadows not done.
- **Experimental** ray-traced shadows phase 4 · alpha-tested occluders in the ray tracing (same switch, still off by default): foliage, fences, models with dither fade and other shadow draws whose fragments may discard no longer stay only in the original shadow map — at packaging `rts_variant.py` emits `_var` variants of the shadow-pass vertex shaders (exporting clip position and interpolants) and rewrites those alpha-tested fragment shaders verbatim into "hit judge" functions collected in `rts_alpha.metal`; at run time it is compiled in the background together with the trace kernels, alpha-tested instances enter the acceleration structure as non-opaque, and at each candidate hit the ray asks the game's own fragment shader (texture alpha, threshold, dither fade, using the shadow-map pixel) whether it blocks. Every shadow draw of a frame can now be in the acceleration structure, so the original shadow maps are cleared back to fully lit and the ray-traced shadows actually take over (on the Mac at the camp every frame previously kept the original map). Also fixed a pre-existing bug: the export draws of a character's parts reused the previous vertex argument block and all wrote into the first part's slot, so character shadows were missing or misplaced (the skinned `_pos` export was affected too). Also: every BLAS is built refittable, refits use separate scratch ranges instead of a barrier each (about 2.2 ms per frame at the camp on a Mac M4 Pro); instances whose export was never encoded and instanced draws stay out of the acceleration structure; empty draws with fewer than 3 vertices no longer block the map clear; `DM_RT_ALPHA=0` turns this off for comparison. The diagnostic log gains a 「光追镂空：第 N 帧」 line (counts in the ray tracing / kept in the original map, with reasons) and a 「光追阴影：没进原因」 line, both carried by the share-diagnostics summary; for debugging, `DM_RT_SHADOW_CHECK=<frame>:<dir>` runs a geometry check from the light and the camera side. The Mac unit test `t_rtshadow` gains an alpha judge case, `t_rts_state` has 40 checks. Not validated on a device. Additions (same phase): (1) performance — half-resolution sun rays with depth-aware upsampling back to full resolution (`DM_RT_SUN_HALF=0` for full resolution), quarter-resolution point-light rays (`DM_RT_POINT_DIV=2|4`) traced only within the light's radius, and the alpha judge counts a ray as blocked after 8 consecutive discarded layers (`DM_RT_ALPHA_MAXREJ`); on a Mac M4 Pro the ray-tracing compute is about 4.3 ms per frame at the camp and 3.0 ms in a dungeon (it had reached 7.5 ms after the export fix); (2) the point-light mask is upsampled by depth, so light / shadow no longer leaks at silhouettes (the `_rt` variants read the full-resolution mask, variant version 6); (3) in levels without a sun (dungeons / indoors) skinned and alpha-tested prepass occluders go through the export and the judge as well, and static occluders are kept for 90 frames (walls that just left the screen keep blocking point lights); (4) export limit per frame 256 → 1024 and slots per mesh 64 → 128 (alpha-tested + skinned exceeded 256 in a dungeon, so whole frames could not clear the shadow maps); (5) the player's own light is recognized while the character walks and weakened (measured on the Mac in a walking run: 「玩家光 已认出」); (6) the per-pass GPU timer (`DM_NVN_PASSGPU` test switch) leaked one block per submission, fixed; (7) the share-diagnostics summary's point-light prefix is now 「光追点光：光源记录」 (it did not match before), plus the 「光追阴影：建好」 line (with the sun / point resolution settings). Resource review: four on / off cycles bring GPU memory and the residency set back to the same level after each switch-off. (8) automatic downgrade (same switch, on by default): the GPU time of the ray-tracing compute pass is measured every frame (two timestamps per frame slot, read only after the GPU is done, never waiting); when the frame's GPU time exceeds 92% of the present-rate budget with ray tracing above 12% for 1 s it steps down one level (0 = as configured, 1 = one point light, 2 = point-light shadows off + half-resolution sun, 3 = quarter-resolution sun, later changed to ray tracing paused, see (14)), below 70% for 8 s it steps up one level, and a quick relapse after a step up doubles the wait (≤ 120 s); `DM_RT_LEVEL=<0–3>` pins a level and `DM_RT_AUTO=0` turns automatic off; on the Mac, with the GPU load test switch, it reached level 3 within 3 s and stepped back to level 0 after the load ended; level changes and a status line every 600 frames are logged as 「光追降档：」 and appear in the share-diagnostics summary; (9) the Mac share-diagnostics export now goes through the same redaction as iOS (it used to replace only the home directory, so container UUIDs in resource paths and the display name went out), with a new display-name rule shared by iOS and the Mac, and the archive no longer carries "._" extended-attribute companions. (10) **experimental** ray-traced AO (plan step 5, off by default, test switch `DM_RT_AO=1`): the plan was to replace the game's ASSAO, but per-frame pass dumps of the camp and the Den of Evil show the game never draws ASSAO on this platform (the passes the assessment inferred from their sizes are depth linearization, depth mips and color downsampling), so it is an added layer instead: 4 cosine-distributed hemisphere rays per pixel at half resolution (`DM_RT_AO_RAYS`), radius 6 (`DM_RT_AO_RADIUS`), a 5×5 depth-aware blur and upsampling, multiplied onto the image after the main pass and before transparents (strength 0.6, `DM_RT_AO_STRENGTH`), firming up wall bases, stone gaps and objects touching the ground; it turns off (and its textures are released) from automatic level 1; about 3 ms per frame extra on a Mac M4 Pro; 「光追 AO：」 log lines are in the share-diagnostics summary. (11) GPU hang protection: when a command buffer reports "Caused GPU Hang" while ray tracing is on (seen in 5 of 141 runs on the Mac, root cause open), the first time it drops straight to the lowest level and does not step up for 120 s, the second time ray tracing is turned off for the rest of the run and the original shadow maps take over (logged as 「光追阴影：GPU 挂起 / 又挂起」, in the share summary; the `DM_TEST_RT_HANG=<frame>[,<frame>]` test switch fakes a hang); the automatic downgrade's "ray tracing alone over half the budget" rule now applies only when the frame time is unknown (it used to step down even with frame headroom, which wrongly dropped AO). (12) GPU hang investigation and hardening: position decoding now has the same bad-data guard as unprojection (non-finite / beyond 1e7 points collapse to the origin and are counted; FLOAT4 / HALF4 exp2(w·13) overflow used to feed Inf into a BLAS); the export write position for non-indexed draws is fixed (Metal's vertex_id includes vertexStart, so with first > 0 the write used to run past the slot buffer); the investigation confirmed the query loop and light gathering are bounded and consecutive frames are separated by queue barriers, and the 'bad points' after unprojection are vertices not referenced by that draw of a mesh drawn in several parts (harmless). (13) Merged into the audit branch (seventh round): shadow maps the game clears with ClearTexture are registered as cleared this frame (on the device not a single in-game frame used to trace); the fallback line names the specific reason; frames in backoff skip the mesh key (about 1 ms per frame on the device); shadow draws outside the TLAS in ray-traced frames are counted by reason (pass not registered / no depth / table full, primitive, format, index segment / vertex range / memory pool, new-mesh quota, mesh pending and more); triangle strips (with restarts) are expanded into lists, quads are handled as lists and empty draws with fewer than 3 vertices count as covered; **shadow maps are handled per map**: maps cleared this frame are cleared back to fully lit and a map the game keeps across frames, not cleared this frame, is left as drawn (on the device whole frames fell back for about 2000 frames after entering the game on "the 3rd / 4th 256x256 map is first attached with a load"). (14) Three issues from the user's recording on the device with 79eaa3f (camp, automatically at level 3): ① **doubled character shadows**: in frames whose shadow maps were not cleared (hysteresis hold, draws outside the TLAS) the variants still took the darker of the ray-traced mask and the original map, layering a hard and a soft shadow; the mask is now bound only when the sun maps were cleared this frame, otherwise the picture is entirely original. ② **only sun shadow maps are cleared**: the camp also has a 512² map lit straight down (read into character shading, affecting how characters are lit) and a 256² hair shadow map, which the sun mask does not replace but which were cleared per map as well; the light direction of the first draw now decides, and maps not lit by the sun stay as drawn. ③ **switching back and forth while walking**: new meshes waited a frame and at most 12 were built per frame, so walking into the camp (200+ new meshes at once) sent about twenty whole frames back to the original picture and the hysteresis held the original for over a thousand frames; meshes queued this frame are now built first in the same ray-tracing encoder, before the TLAS (with a barrier after each build), and enter the TLAS in the same frame, with up to 32 meshes / 200,000 triangles built per frame (Mac camp walk, 100 s: hysteresis hold 3959 → 30 frames, frames with draws outside the TLAS 74 → 5, picture switches 11 → 3). ④ **level 3 now pauses ray tracing**: it used to be the sun at quarter resolution, whose stone-wall shadow turned into stair steps that crawled and flickered when the camera moved, for little saving; level 3 now shows the original picture, and the frame GPU time still feeds the automatic downgrade, which steps back up once there is headroom. A new 600-frame line 「光追阴影：阴影图 …」 lists each shadow map's size, layer, light direction and whether it was cleared.
- **Experimental** ray-traced shadows · partial fallback and sun-map selection (same switch, still off by default; fixes from the user recording on the device with 79eaa3f): ① until now a single shadow draw outside the acceleration structure (new mesh pending, build quota full this frame, unsupported format) sent the whole frame back to the original shadows; at the camp / in the forest the picture was ray traced only 26% / 31% of the time and jumped between ray traced and original, shadows growing and shrinking. Now sun shadow draws that are in the acceleration structure are not drawn into the shadow map, the others are drawn as original, the `_rt` variants take the darker of mask and map, the maps are no longer cleared back to fully lit, and one draw outside no longer drags the whole frame back (`DM_RT_SHADOW_PART=0` restores the old "clear the whole frame" for comparison); the per-frame BLAS build cap drops to 60k triangles, spreading the 200+ meshes of the camp over a dozen frames. ② The sun direction now comes from the light of the largest square shadow map (the cascade); it used to be the light of the frame's first shadow draw, which was wrong whenever the hair / top-down soft map was drawn first, after which the cascade was kept as "not the sun" and two shadows pointed different ways; non-sun maps such as the top-down soft shadow (light straight down) and the hair shadow are drawn as original and kept out of the acceleration structure. ③ The automatic downgrade is now 0 as configured → 1 one point light, AO off → 2 alpha-tested occluders (leaves, grass) drawn as original, no judge → 3 point-light shadows off as well → 4 ray tracing paused (original shadows), so cave torches keep their point-light shadows through level 2; `DM_RT_LEVEL=<0–4>`. Frames that built more than 20k triangles of meshes and the first 180 traced frames no longer drive the downgrade (on the device it hit the bottom within 10–20 s of entering, the first window holding character select, loading and the first mesh builds). New diagnostic lines "光追阴影：局部回退 至第 N 帧" (skipped draws, draws kept in the sun map, skipped frames that failed to trace) and "光追阴影：阴影图 第 N 帧" (each map's light and which map the sun came from), included in the share-diagnostics summary; unit tests `t_rts_gate` sections 13–20, `t_rts_flicker` section 7.

- Controller mode keeps the experience line (`Lv · % · FPS`) on both platforms: the touch overlay is no longer hidden as a whole, it draws only that line per the shared `dm/host/dm_hud_mask.h` (the original controller bar has its own life / mana numbers). Android: the Custom page no longer rings when the controller selects a row that cannot fully scroll into view (`dm_custom_scroll.h`).
- Graphics tab **Show frame rate** switch, second row, on by default (moved from the Custom tab, where it was off by default, at the user's request on 2026-10-28): the actual presented frame rate, refreshed every 0.5 s, is appended to the bottom-bar experience line ("Lv 17 · 23% · 60 FPS") in the same game-font glyphs and color, without a backing plate; it is hidden whenever the bar is (e.g. with a panel open). `DM_FPS=120` with `DM_PRESENT_HZ=120` is a 120 Hz experiment switch for the pacer, ProMotion request and 3D scale controller; not a settings option.
- Auto render resolution closed loop: with the 3D ratio at its floor and frames still dropping, the output steps down (Balanced → Eco) and recovers after 60 s clean; pure controller `dm_res_auto_step` in `dm/host/dm_res_cap.h` with unit tests, driven from the existing frame-interval controller in `hle_oe.c`. Not device-verified yet.
- Graphics tab **Resolution** slider (Auto / Eco / Balanced / Native) capping the whole-frame output size by pixel budget (4.0 / 2.07 / 2.8 MP / none), aimed at very dense screens such as the iPhone Duo inner screen where the UI layer, final composite and present blit at 2852x2006 dominate GPU time regardless of the 3D ratio. Shrink-only, aspect-preserving, applies live, defaults keep regular iPhones unchanged. Pure budget math in `dm/host/dm_res_cap.h` with unit tests; localized in six text sets. Implemented and unit-tested; not yet device-verified or power-measured.
- Auto render resolution now picks its pixel budget by GPU generation parsed from the Metal device name (A16 and earlier 2.07 MP, A17 Pro / A18 2.8 MP, A18 Pro / A19 3.8 MP, A19 Pro / A20+ 4.0 MP, M series 4.5 MP); screens above 4.5 MP native (the iPhone Duo inner screen) take the Balanced 2.8 MP budget, after a 10-minute device run under full-screen spell effects showed Native pinned at ~15 ms GPU per frame and Eco at ~10 ms with identical fps and dropped frames. Unit-tested; the GPU-generation table is not device-verified on older chips.
- Launch-time detection of an iPhone running the package with the iPad identity (a re-signing tool's "iPad mode"), which makes iOS letterbox the game at the iPad aspect ratio: logged as a failure and shown once as an alert with the fix. Diagnosed from a user report on iPhone 16 Pro; the shipped package itself is universal.
- Measurement build switch: `DM_DIAG_SAMPLING=1 dm/ios/run.sh build`, or a `Documents/diag_sampling.txt` file on any build, turns on per-pass GPU timing, per-thread CPU and heat-attribution sampling into `Documents/diag/`. Diagnostic output only; never set for release builds.
- Added on-device Graphics settings and notification screenshots to both READMEs, with image metadata removed. Graphics screenshots now show the five-tab revision and use distinct filenames.

- Dedicated Graphics tab (second in Options, right after Audio; rows are render resolution, frame rate, then the MetalFX switch and profile, so render resolution is not next to upscaling) with an independent MetalFX enable switch (labelled experimental), a four-position profile slider, and a separate left/right 30 / 60 FPS selector. Help uses smaller, muted secondary text. New labels and application guidance are localized in Chinese, English, Spanish, Latin American Spanish, Russian and Korean.

- Experimental MetalFX spatial upscaling with Auto, Eco, Balanced, Quality and Original profiles. Apply switches profiles live without restarting; render-target recreation may briefly pause rendering. Only 3D color is scaled, retaining the original mask and subsequent UI. Unsupported devices or initialization failure use the original pass.

- Adaptive front-end scene coverage and bottom-edge layout, with a centered interface and safe-area-aware positioning.
- Notification frame generation using locally supplied game artwork. Corner ornaments remain unstretched; the center uses an opaque shaded background.
- Optional build-time main-font override through `DM_UI_FONT`, including original-font fallback for missing characters. Disabled by default; no font files are distributed.
- Stroke-darkening levels for the optional font: `DM_UI_FONT_WEIGHT=0..8` widens every stroke of the requested font by 5‰ em per level (FreeType-style outline emboldening in `font_override.py`), re-centred so advances, line metrics, fallback glyphs and private-use icons stay unchanged; levels 2–3 fill in the grey hairlines of a kai face without turning it bold, level 6 reaches the ink density of the original `BlizzardGlobal`. New `font_sample.py` renders Mac sample sheets, including a simulation of the Graphics Resolution cap (text rasterised at the smaller output size and upscaled whole-frame), which is why lowered render resolutions soften UI text; the vector font cannot pre-compensate the upscale, so the documented trade-off is a heavier level with Auto/Balanced. Implemented and unit-tested (three new tests); Mac samples and macOS App runs at levels 2 and 4; on an iPhone Duo level 4 was too dark and **level 3 was accepted by eye** (full panel coverage pending).
- Focused regression tests for front-end coordinate conversion, quest-control classification, notification frame construction and font composition.
- English and Simplified Chinese project, build, verification and change documentation.

### Fixed

- `DM_FPS=120` without `DM_PRESENT_HZ=120` no longer stalls the game: the host pacer now follows the 120 FPS target, and while the display link drives presents its target can no longer drift ahead of real time (it used to drift tens of seconds, and one late link callback then put the acquire fallback to sleep until then).

- Route enhanced UI notifications through a bounded queue drained on the game main thread. Paused-menu deposit feedback no longer waits for the server to resume; controller gold/item tooltips no longer move the notice.
- Fit the notification frame to native font measurements, preserving fixed corner and medallion art with single-frame slices.
